# Decisions

Every ambiguous point resolved during the build, with the reason. Newest last.

| # | Decision | Reason |
|---|----------|--------|
| D-001 | Crates are named `forhunt-core`, `forhunt-output`, `forhunt` (binary), not `core`/`output`/`cli`. | A crate named `core` shadows Rust's built-in `core` crate; prefixed names are also publishable on crates.io. |
| D-002 | Release profile uses `panic = "unwind"`, not `"abort"`. | The spec requires that corrupt EVTX never crashes the tool. The `evtx` decoder can panic on malformed data; with unwind, each chunk runs under `catch_unwind` and a panic is counted as a bad chunk. The cost is negligible (no measurable throughput change; slightly larger binary). |
| D-003 | `evtx` 0.12.3 is pinned (`=0.12.3`) with default features off. | 0.12 removed the `BinXmlOutput` visitor; the only public record-level output is its compiled JSON/XML renderer. Pinning protects the hidden-API-free hot path from upstream changes. Default features pull in the `evtx_dump` CLI deps we do not need. |
| D-004 | Hot path renders each record to JSON with `evtx` and decodes it with a purpose-built scanner into a borrowed `EventView` (no `serde_json::Value`, strings borrowed unless escaped). | Measured: the serde visitor decoder cost ~200 ms per 30 MB file single-threaded, more than the render itself. The custom scanner (SWAR quote search, single UTF-8 validation per record) is ~2x faster. See docs/PERF.md. |
| D-005 | Stable event id = `<file key>:<record id>`, file key = first 32 bits of BLAKE3 over (file size, first 68 KiB, last 68 KiB). | `file + record id` collides when two hosts both have `Security.evtx`; a content key survives copies/renames. Hashing whole multi-GB files would add a full extra read; sampling header + first and last chunk is unique in practice (chunks carry host names, timestamps, record ids). Full SHA-256 of evidence is the job of the skill's evidence step. Byte-identical inputs are detected (same key) and opened once. |
| D-006 | Units of parallel work are 64 KiB chunks across all files, flattened into one task list and run on a rayon pool with a bounded in-flight window; results are reassembled in (file, chunk) order. | Gives file-, directory- and chunk-level parallelism with one mechanism, deterministic output for any `--threads`, and memory bounded by `window x chunk output` regardless of input size. |
| D-007 | Timestamps are stored as 100 ns ticks since the Unix epoch (`Ts(i64)`). | FILETIME resolution; nanoseconds in an i64 overflow before 1677, and corrupt records carry 1601-01-01. |
| D-008 | Time filters never use the EVTX record header time (the *write* time, which can lag `TimeCreated` by days for forwarded or late-written events). The fast path pre-checks the exact `TimeCreated` FILETIME substitution before decoding; the JSON path renders every record and checks `TimeCreated`. (Until v0.2.2: a header-time pre-check with 24 h slack, which silently dropped events skewed by more than a day.) | Measured 2026-10-24 (best of 3, `-n 0 -F jsonl`): synthetic 2 GiB corpus, 1 h window, `search` 0.83 s -> 0.75 s and `timeline` 0.74 s -> 0.73 s (fast path, exact pre-check); all chunks forced through the JSON path (`--slow-decoder`) 0.85 s -> 1.11 s (+31%); 56,930-event lab set 0.01 s either way. Dropping the pre-check altogether cost +45% on the corpus. Lossless first (owner rule). |
| D-009 | `--field Name=value` is case-insensitive; when either side is hexadecimal (`0x...`) the comparison is numeric. `Name!=value` and `Name~substring` are also supported. `--regex` is case-insensitive and takes `[Name=]PATTERN`. | Windows writes the same value as `0x17` or `0x00000017` depending on version (found by the AD research agent in real samples). Analysts and checklists should not have to care. |
| D-010 | `--channel` accepts the full name, a short alias from the field map (`Sysmon`, `PS`, `TS-LSM`...), or a `*` glob; no implicit substring matching. | Predictable: `System` must not match `Microsoft-Windows-Kernel-System`. |
| D-011 | Default formats: `parse` -> jsonl, `search`/`timeline` -> llm (cap 200), `stats` -> llm. | The tool is designed to be driven by an LLM with a limited context; full dumps are explicit. |
| D-012 | Exit codes: 0 ok, 1 error, 2 usage (clap), 3 no input files, 4 corrupt input with `--strict`. A search with zero matches exits 0. | Corruption must be distinguishable from errors; "no match" is a valid answer for the analyst workflow (the summary line says `matches: 0`). |
| D-013 | Truncated files: the partial last chunk is zero-padded and parsed without checksum validation, so records before the cut are recovered; a warning is printed. | Truncated logs are common in triage collections; dropping a whole chunk loses evidence. |
| D-014 | Name availability: `forhunt` and `forensic-hunter` return no results on crates.io (`cargo search`, 2026-10-21). `brew search` could not be run (no Homebrew in the build container, formulae.brew.sh blocked); later checked on a Mac: free. | Spec asks to check names before publishing. |
| D-015 | Research subagents run on Sonnet, mechanical tasks on Haiku; the Rust core stays on the main agent. | User instruction (cost). |
| D-016 | `cargo deny` ignores RUSTSEC-2021-0153 (`encoding` unmaintained). | Transitive dependency of `evtx` (ANSI code pages); no vulnerability; cannot be removed without forking evtx. |
| D-017 | The CI performance gate counts instructions (valgrind/callgrind, 1 thread) of `forhunt parse/search/stats` on a fixed 32 MiB synthetic corpus, for the head and the base revision built in the same job; fails above +3%. | Wall-clock time on shared runners varies by 10-20%; instruction counts are reproducible to <0.01% (measured). Comparing against the base built in the same job avoids toolchain drift in a stored baseline. criterion stays for local micro-benchmarks, hyperfine for README numbers. |
| D-018 | Fixtures are generated by `tools/evtx-gen` (template-based writer, fixed attack scenario on fake hosts/IPs from RFC 5737) and committed (~5 MiB); CI checks they are byte-for-byte reproducible. Public samples (evtx crate samples, EVTX-ATTACK-SAMPLES, GPL-3.0) are only downloaded by scripts, never committed. | "Never commit real logs." |
| D-019 | Hayabusa 4.x replaced `csv-timeline`/`json-timeline` with `dfir-timeline -t csv|json|jsonl`; the skill documents both and recommends `-p verbose` so detections carry `EvtxFile`, which lets `forhunt hayabusa` attach forhunt ids. | Found by running Hayabusa 4.2.0. |
| D-020 | Event ids use the record header id; `show` also accepts the `System/EventRecordID` (Hayabusa's `RecordID`), and `forhunt hayabusa` translates it to the header id. | Exported/filtered logs renumber record headers (seen in EVTX-ATTACK-SAMPLES: header 1..7, EventRecordID 8046). |
| D-021 | Inputs are read with positional reads (`pread`/`seek_read`), one 64 KiB chunk at a time, instead of `mmap`. | Deviation from the brief's "mmap input", measured: with mmap every touched page counts as resident memory (2.0 GiB RSS on a 2 GiB corpus), contradicting "bounded memory"; chunks are copied into an owned buffer for the parser anyway, so mmap saved nothing. With pread, RSS is 25 MiB on the same corpus at equal speed. Files are still opened read-only. |
| D-022 | Fast decoding path: template definitions are compiled once into a plan (substitution index -> System value / EventData field) and record values are read directly from chunk bytes, including Windows' nested `EventData` templates (BinXML substitution). Chunks containing any shape the plan cannot reproduce exactly (UserData, unnamed Data, ANSI strings, floats, arrays...) go through the JSON path as a whole. A hidden `--slow-decoder` forces the JSON path; CI asserts both paths give byte-identical output on the fixtures; locally verified identical on ~156k events from 4 public corpora. | 1.9x single-thread on real Security logs; keeps exact output parity and record order. |
| D-023 | evtx-gen writes Windows' real layout (outer System template + nested EventData template) for all providers except PowerShell, which keeps the flat layout. | Fixtures, the CI perf gate and the benchmark corpus must exercise the same paths as real logs; first fast-path version only matched the synthetic flat layout (found by measuring coverage on real samples: 1 of 481 chunks). |
| D-024 | Hayabusa is shown in benchmarks for reference with a single run on a smaller corpus. | It evaluates thousands of Sigma rules (12+ minutes per pass on the 2 GiB corpus on 4 cores); it does different work than parsing. |
| D-025 | `forhunt checklist` sweeps all checks in one pass from `checklists.json` (generated from the YAML by `scripts/gen-checklist-index.py`, so the binary needs no YAML parser). It pre-fills `HIT?` / `NO_HIT` / `LOG_SOURCE_MISSING`; the analyst must resolve every `HIT?`. | Walking 242 checks with separate searches means hundreds of passes over the evidence (minutes to hours on multi-GB cases) and invites silently skipped checks. Judgement (true positive, NOT_APPLICABLE, thresholds) stays with the analyst. |
| D-026 | `forhunt hayabusa -g` groups detections per (rule, level, host) with counts, first/last time and up to 5 forhunt ids. | Hayabusa output is highly repetitive (22 identical GPO detections in the worked example); grouping cuts context use ~3x without losing pivots. |
| D-027 | CSV output follows EvtxECmd's column names and order (plus `ForhuntId`), with `TimeCreated` as `yyyy-MM-dd HH:mm:ss.fffffff`. Content differs where EvtxECmd relies on its per-event maps: `MapDescription` and `PayloadData1..6` come from forhunt's field map (`Name: value`), `Payload` is a flat JSON object of all fields. | User request: open the output in Timeline Explorer and similar tools. Matching the de-facto layout keeps analysts' saved views and column habits; only the format is reused, no code. |
| D-028 | Multiple inputs are concatenated by default; `-O DIR --split file|host` writes one file per input file (name = relative path, separators -> `__`) or per computer. Output stays in deterministic (file, record) order per file; at most 128 output files are kept open (LRU). `parse` gains `--computer`. Not available for `timeline` (one global time order) or with `--limit`. | User request (multi-endpoint collections). Per-host splitting is by the `Computer` field, not by folder, because collections are not always organised by host. |
| D-029 | Before `evtx` parses a chunk on the JSON path, forhunt follows the 64 string-table chains in its own copy of the chunk and cuts any cycle (the chunk is reported bad). | `evtx` 0.12.3 stops a chain only on a 0 or self link: a 2-node cycle in a corrupt chunk looped forever (found by fuzzing in the review); `catch_unwind` cannot stop a loop. The fast path does not walk these chains. |
| D-030 | When two different files share a sampled file key, the later one (input order) is keyed by a BLAKE3 hash of its whole content instead of being skipped; byte-identical files are still opened once. `show` falls back to full-content keys when a sampled key matches no input. | A damaged copy with intact ends (same size, same first/last chunk) was silently dropped as a duplicate, hiding its bad chunks from `--strict`. |
| D-031 | `--regex Name=PATTERN` applies to field `Name` on events that have it; on other events (and when `PATTERN` alone does not compile) the whole argument is matched against every value. | `pAA==$` (base64 padding) was read as field `pAA` and silently matched nothing. A name/pattern heuristic cannot separate `SQBFAFgA=` from `CommandLine=`. |
| D-032 | `forhunt checklist` does not run queries holding example values (RFC 5737 IPs, `jdoe`, `example.com`, fixed `--since/--until`), and gives `NO_HIT` only when every query of a check was evaluated; otherwise `REVIEW`. | Pivot queries with placeholder values produced false `NO_HIT`s on a real brute force (FH-INIT-002/005). |
| D-033 | `--threads` is limited to 1024 (usage error above). | `-t 99999` spawned 99,999 threads. |
| D-034 | The release workflow can be run by hand without a tag as a dry run (all 5 targets built and packaged, nothing published); tags must match the `Cargo.toml` version; tags with a `-` are published as pre-releases and skip the Homebrew tap. | The first release must not be the first time the cross builds run. |
| D-035 | v0.1.0 was published by running the release workflow by hand with `tag: v0.1.0`; the workflow created the tag on the built commit. | The build session's git proxy refuses tag pushes (HTTP 403, B-005). A pushed tag still triggers the same workflow. |
| D-036 | NTFS support starts with `$MFT` and `$UsnJrnl:$J` (MFTECmd's scope), written from the on-disk format; no code from MFTECmd or the `mft` crate. The `mft` crate's `mft_dump` and its sample serve only as a differential reference. | User choice of the next Zimmerman tool; MFT gives the most timeline value after event logs and is where speed matters (multi-GB tables). |
| D-037 | An `$MFT` record becomes one event per distinct timestamp of its `$STANDARD_INFORMATION` (event id 16) and of its best `$FILE_NAME` (48, Win32 name preferred over DOS 8.3), with a `MACB` field; each event carries path, size, flags and all eight timestamps. Ids are `entry*8+n`. | Super-timeline convention (one event per time, like mactime/plaso), so `timeline` merges file activity with event logs; carrying all timestamps keeps one event sufficient to judge timestomping. The event-id numbers are the NTFS attribute type codes (0x10, 0x30) that MFTECmd also uses as column suffixes. |
| D-038 | Timestomp indicators are explicit fields present only when true: `SiLtFn` ($SI created < $FN created), `uSecZeros` ($SI created with no sub-second part), `Copied` ($SI created > $SI modified); likewise `Deleted` and `IsDirectory`. | Keeps `llm` output short (absent = false) while letting `--field SiLtFn=true` find them. |
| D-039 | Paths start with `.\` (volume root, drive letter unknown); a parent whose sequence number does not match the reference (reused entry) gives `.\[orphan 0x<entry>-<seq>]`; a deleted parent matches with `seq - 1` (NTFS bumps the sequence on deletion). | Never print a wrong path for a reused directory. |
| D-040 | `$J` event ids group the accumulated reason flags into an action (1 created, 2 deleted, 3 renamed, 4 data, 5 metadata, 6 close only; priority delete > rename > create > data > metadata). Parent paths are resolved with an `$MFT` found in the journal's folder or its parent (KAPE/Velociraptor layout), using a per-run cached path table. Ids are byte offsets. | `-e 2` (deletions) is the common question; reasons stay available in `Reason`. Offsets, not USN values, so ids stay valid for extracts that dropped the sparse head. |
| D-041 | NTFS metadata has no host name: `computer` is empty, host facets skip it, `--split host` files it under `_unknown`, `--computer` filters it out. Sources declare `is_log() = false`, so `stats` reports no record-id gaps or quiet periods for them. `show -F xml` (alias `raw`) prints a hex dump of the record. | A guessed host would be wrong; the SYSTEM hive (registry support) can supply it later. Gap analysis only makes sense for logs. |
| D-042 | No Intel macOS release: macOS ships aarch64-apple-darwin only; the Homebrew formula requires arm64 on macOS and `install.sh` points Intel Macs to `cargo install`. Binaries stay unsigned/un-notarized (no Apple Developer account); the README documents the Gatekeeper workaround. | Owner request (2026-10-24): Intel Macs are no longer needed; saves a macOS build (10x Actions minutes). |
| D-043 | The release workflow pushes the formula to `0xRD/homebrew-tap` with an SSH deploy key (`TAP_DEPLOY_KEY` secret, write access to the tap only), like Hector's release, instead of a fine-grained PAT. | A deploy key is scoped to one repository and never expires silently; one key per project keeps revocation independent. |
| D-044 | Library API for other programs (forhunt-viewer opens EVTX/NTFS directly): `forhunt_core::input::open_all` (expand, open in parallel, skip duplicates; warnings returned, not printed) and `forhunt_output::export::write_all` (every event in input order through a `Writer`, progress callback, cancel flag). The CLI's `Ctx::open` is now a thin wrapper over `open_all`. Consumers pin a release tag as a git dependency. | One implementation of input handling and output layout: the viewer's CSV is byte-identical to `forhunt parse -F csv` (checked on a 56,930-event lab set), so ForhuntIds and `forhunt show` keep working. |
| D-045 | `checklist` evaluates each query with its own channel and event ids (falling back to the check's when the query names none) and reports coverage per query: source events, and of those the ones carrying every positively tested field. Nothing covered gives `LOG_SOURCE_MISSING`; `--actionable` lists only HIT?/REVIEW rows. | Lab evaluation (2026-10-24): gating by the check's single channel hid 53 of 273 checks' off-channel queries (Defender disable missed), and 4688 without CommandLine read as NO_HIT. |
| D-046 | `llm` output: per-event short names in the map (`rename`, 4688 `ProcessId` -> `ppid`), never a repeated key in `d`, line breaks/tabs collapsed to one space, `--fields` projection; `stats` folds a short host name into its single FQDN and groups 4719 per account; `-f Name!~text` negates a substring. | Same evaluation: duplicate `pid` lost the parent, multi-line values and 4719 bursts wasted context, "AD01" and its FQDN counted as two hosts, noise could not be excluded without grep. |
| D-047 | Field conditions compare values the way analysts copy them: GUIDs with or without braces (`{42e0bcd9-...}` = `42E0BCD9-...`), timestamps at microsecond precision (Windows' 7 digits match), multi-line values with whitespace runs collapsed (as `llm` shows them); `Data[1]` also finds a lone unnamed `<Data>`; `EventRecordID` is the System value; `-c`/`--computer` take comma lists; `--computer FQDN` keeps events logged under the short name; `--fields` selects among all fields; `stats` reports record-id gaps inside chunks and none (nor quiet periods) under a filter; summary counts are exact. | QA against an independent python-evtx oracle on the 56,930-event lab set (2026-10-24): each of these returned nothing, the wrong events or wrong counts where the analyst expected a match. |
| D-048 | Silent losses become warnings where they cannot be fixed: `show` says when an id's record header id and System/EventRecordID designate different records (D-020) and gives the other forhunt id; `--split host` appends short-name events to the single FQDN file (after writing, out of time order, with a warning); `-O DIR` lists files it did not write; `input::open_all` warns about two files holding the same log (channel and computer, files mixing hosts excluded) with overlapping EventRecordIDs. | Owner rule (2026-10-24): an analyst must never lose events silently; correct and slower beats fast and lossy, and what cannot be fixed must be loud and documented. |
