# Sources: lateral movement, remote access, initial access

Research date: 2026-10-21. Files: `checklists/lateral-movement.yaml`, `checklists/remote-access.yaml`,
`checklists/initial-access.yaml`, `logontypes.md`.

## How the sources were read (important)

The research sandbox only allowed outbound access through a policy proxy. `learn.microsoft.com`,
`attack.mitre.org`, `jpcertcc.github.io`, `thedfirreport.com`, `ponderthebits.com`,
`ultimatewindowssecurity.com`, `www.elastic.co`, `docs.specterops.io`, and the web archive were all
refused (HTTP 403 on CONNECT or DNS failure), and the WebFetch tool could not resolve any host. What was
reachable was GitHub over git/raw. So:

- Rule projects (SigmaHQ/sigma, Yamato-Security/hayabusa-rules, WithSecureLabs/chainsaw) and the JPCERT/CC
  Tool Analysis Result Sheet repository were read from shallow `git clone` checkouts of their default
  branches (dates: sigma and hayabusa-rules 2026-10-21, chainsaw 2026-10-14, ToolAnalysisResultSheet last
  commit 2017-12-04). The URLs below are the GitHub blob URLs of the files I opened. No rule body was copied;
  checks are written in my own words.
- MITRE ATT&CK technique ids were validated against the `mitre/cti` STIX bundle (not the website). It shows
  T1562.004 revoked and replaced by T1686 (T1686.003 Windows Host Firewall); older tooling still uses T1562.004.
- The Microsoft Learn event-reference pages (4624, 4625, 4648, 4697, 4698, 4740, 4768, 4771, 4776, 5140, 5145...)
  were NOT read. No `verified: true` claim relies on them; two independent rule/lab sources were required instead.
- A handful of WebSearch result summaries were consulted for items nothing else covered (see the last section).
  They are not opened pages and therefore are not listed in any check's `sources`.

## Open questions

1. Microsoft's authoritative field semantics for 4625 Status/SubStatus, 4740 (TargetDomainName as caller
   computer), 4771, 4776, 5142-5144 and the 4624 field descriptions were not confirmed from Microsoft Learn.
   Re-verify FH-INIT-003/004/009/010 and FH-RMT-016 against it.
2. Is `KeyLength 0` on an NTLM type 3 logon a usable pass-the-hash indicator? JPCERT's lab recorded 128 for
   password logons *and* for Mimikatz/WCE pass-the-hash (FH-LAT-012). Needs a modern-Windows lab test.
3. Meaning and fields of RdpCoreTS 131/98/140, LocalSessionManager 40, WinRM/Operational 91/142/161/168 and
   SMBServer/Security 551 are unconfirmed (snippet-level only); build a lab capture before trusting them.
4. Which logon type does an RDP *reconnect* produce (7 vs 10) on current builds, and does Restricted Admin log
   as type 3? JPCERT did not state the reconnect type.
5. Does `wsmprovhost.exe` as parent/host process hold on all supported WinRM paths (WinRS uses winrshost.exe)?
   JPCERT's older sheets show WmiPrvSE instead; Sigma only.
6. Impacket defaults (service names, `__<epoch>` output file, random service name length) change between
   releases and forks (NetExec etc.); FH-LAT-002/008/020 need re-checking against current Impacket.
7. Third-party VPN, firewall, reverse proxy, IIS access logs and e-mail gateway telemetry are outside EVTX; the
   initial-access checklist can only mark them as blind spots (FH-INIT-015).
8. Thresholds (distinct-account counts, windows) in FH-INIT-001/005 and FH-RMT-017 are starting points, not
   sourced values.
